# Changelog

## Unreleased

- **Modal endpoint accepts long recordings and more file types.** Audio up to 30 minutes (was 120 s) and uploads up to 500 MB (was 25 MB). Long audio is transcribed 8 windows (4 min) per batch, so GPU memory stays flat. GPU request timeout 20 min, endpoint timeout 40 min with 4 GB memory, ffmpeg decode timeout 5 min. Added AC3/E-AC3, MP2, WavPack, APE, TTA, AU, VOC, DSF, Musepack, Speex and GSM, plus video files (AVI, FLV, MPEG-PS, MPEG-TS; MP4/MOV/MKV already worked) whose first audio track is used. AVI, FLV, WavPack, APE, TTA, AU, Musepack and MPEG-TS files sent as `application/octet-stream` are recognised and decoded instead of read as raw samples. Playlist, concat, image and device inputs stay blocked. Checked locally with ffmpeg 9.0: MP4, MKV, AVI and MPEG-TS video and a 10-minute MP3 decode to the right length. **NOT VERIFIED** on Modal: long-audio GPU time and memory, and Modal's own request-size limits for very large uploads.

- **GPU now serves two fine-tuned Whisper models instead of the CDLI checkpoints.** The `english` and `swahili` keys load full Hugging Face exports from the Modal Volume `sauti-adapt-finetuned-model` (`/english`, `/swahili`), configured in `SERVED_MODELS` in `ml/modal/server.py`. The CDLI weights stay stored in `sauti-adapt-cdli-cache` and supply `preprocessor_config.json` / `generation_config.json` when a folder lacks them, refused when mel bins or vocabulary differ. `ml/modal/finetuned_models.py` checks each folder before loading (safetensors only); an incomplete folder makes only that key return `503`, with the reason in the container log. Responses add `model_id` and a `revision` fingerprint of the uploaded files, and the speech API labels comparison rows with that `model_id` instead of the CDLI repo. Personalized keys return `503` because their adapters were trained on the CDLI base. The volume is looked up without `create_if_missing`, so a misspelt name fails the deploy. Class and app names are unchanged, so `warm.py` and the endpoint URL keep working. Tests cover folder checks and the `model_id` label. **NOT VERIFIED:** loading on Modal (needs a deploy), the uploaded folders' contents, and the fine-tuned models' accuracy.

- **Modal endpoint accepts common audio files**, not only raw float32. WAV, MP3, M4A/AAC, OGG/Opus, WebM, FLAC, AIFF, AMR and WMA at any sample rate or channel count are decoded with ffmpeg in the CPU API container (`ml/modal/audio_input.py`) to 16 kHz mono float32. Raw float32 (`application/octet-stream`, as the speech API sends) skips ffmpeg, and a trailing partial sample is dropped instead of rejected. Uploads are capped at 25 MB and decoding at 60 s. ffmpeg only opens local files in whitelisted audio containers, so playlist and concat inputs cannot make it read other files. Clips under 0.3 s now return `413` instead of a server error. Tests in `ml/modal/tests` run in CI with real ffmpeg. Checked locally with ffmpeg 9.0 on MP3, M4A, Opus, WebM, FLAC, OGG, AIFF and WAV. **NOT VERIFIED** on Modal (Debian's ffmpeg 5.1) until redeployed.

- **Modal CDLI GPU endpoint deployed and working** (workspace `ulla39254`, 2026-11-07). `ml/modal/serve.py` is renamed to `ml/modal/server.py`; the deploy workflow and docs use `modal deploy ml/modal/server.py`.
  - Fixed: the GPU container crashed at startup (`No module named 'fastapi'`, because every container imports the module), so requests were cancelled. Earlier `401`s came from the `sauti-gpu-auth` secret missing or holding a different value in the hosting workspace.
  - One GPU container (L4, A10G fallback) holds both CDLI checkpoints and serves every model key, so a comparison never starts a second container. Hugging Face revisions are pinned; startup makes no network calls once weights are cached. Startup and request timeouts are separate.
  - Audio up to 120 s, split at quiet points into ≤30 s windows. Output up to Whisper's 440-token ceiling per window, scaled by audio length; silent windows are skipped, so silence returns an empty transcript instead of invented text.
  - A personalized key without an installed adapter returns `503` instead of crashing the container.
  - `ml/modal/warm.py` opens a warm window (default 10 h, max 12) that keeps one container loaded; `enforce_warm_window` releases it when the window ends and restores it after a redeploy.
  - Auth is the single service bearer token (`sauti-gpu-auth`). Per-team partner tokens and Modal proxy auth were tried on this branch and removed by agreement, so the speech API needs no proxy credentials.
  - Measured: warm 18–30 s real clips 3.7–4.9 s per request (under 1 s of GPU time), cold start about 15 s (was 105 s or a 300 s timeout). **NOT VERIFIED:** accuracy for Sauti co-designers, and personalized adapters (none trained yet).

- The first account created while `SAUTI_PILOT_PROFILE_ID` is set (and unclaimed) receives that profile ID automatically; later accounts get random IDs, so one person's private adapter is never shared.

- **Working-demo path for voice control.** Previously nothing in the app could train a model: training was a console command, so `SPEECH_MODE=prototype` still answered `NO_VALIDATED_PERSONAL_MODEL`. Added `POST /v1/train` and `GET /v1/train/{profile_id}` (owner only, background job), automatic stratified train/calibration/test splitting from one recording session, and a "Build my voice model" button on step 4. Tests use artificial tones; real speech is NOT VERIFIED.
- **Demo-grade policy** (`SAUTI_DEMO_MODE=true`): lower unknown-clip minimum, release status `demo-validation-passed`, never accepted unless demo mode is on at recognition time. The normal pilot gate is unchanged and still refuses the same small evidence.
- Encoder reads one hidden layer (default 8) and trims silence before mean pooling. The layer and trimming are part of the model signature, so old models are rejected rather than silently mismatched, and the retention purge deletes cached embeddings under the same key. `python -m sauti_ml.layer_sweep` ranks layers on a participant's own clips. Defaults are NOT VERIFIED on atypical speech.

If that fails, clicks fall back to synthetic ones.
- Head pointer precision (Research/001). The pointer snaps to any clickable, not only links, measured to the target's edge, and the snapped target is framed. Mouth click freezes the pointer as the mouth starts to open and clicks once per opening; Nutshell re-clicked every 800 ms while the mouth stayed open. A picker with large numbered tiles appears when a click lands between small targets. The follow rate depends on distance, and the side panel adds Pointer speed and Steadiness. A target test page is in `apps/headway/Research/`. 19 tests pass. Not yet measured with a person.
